# Подключение моделей художника

Порядок работы художника описан в `docs/05_ART_AUDIO.md` §4. Твоя задача — подключить модели, **не меняя игровую логику**.

1. Найди новые или изменённые файлы: `git status art/models`. Путь `art/models/<категория>/<id>.glb`, где id из `content/*.json`.
2. Прогони тест моделей (этап 2 плана): `godot --headless --path . -s res://tests/run_tests.gd -- --filter=models`. Он проверяет:
   - id существует в контенте;
   - габариты разумны: детали стройки кратны 2 м ±5%, игрок 1,6–2,0 м, лодки по `boats.json`;
   - клипы анимаций названы по таблице §4.5;
   - объекты `-glow` есть там, где нужен свет (окна, огонь, глаза).
3. Если тест упал из-за модели, **не правь модель кодом** (масштаб, поворот). Опиши художнику, что не так и как исправить в Blender, со ссылкой на пункт §4.
4. Если модель в порядке, `ModelLibrary` подхватит её сама. Проверь сцену скриншотом и сравни с заглушкой: не «съехали» ли сокеты стройки и ватерлиния лодки.
5. Материал модели заменяется шейдером `prop.gdshader` с палитрой `art/palette.png` (туман работает только так). Не оставляй стандартный материал из glb.
6. В `CHANGELOG.md`: «модели: …», в ответе — список подключённых и отклонённых моделей с причинами.
